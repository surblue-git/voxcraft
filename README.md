# VoxCraft — 日本語長文 音声入力ツール

自宅PCで動くローカルWhisperを使い、Obsidian上で日本語の長文を「話すだけ」で書くためのツール。
Windows(Desktop) と Android(Obsidian Mobile) の両方で同じプラグインが動く。

## 特徴（設計方針）

- **無料・ローカル認識**: 自宅PCで faster-whisper（既定 `kotoba-tech/kotoba-whisper-v2.0-faster`）。クラウド不要。
- **沈黙で切れない待機**: マイク入力はユーザー操作か「入力終了」の発話まで待機（PC音声の文字起こしだけは5分無音で自動停止）。
- **擬似リアルタイム**: 息継ぎ（既定0.5秒）ごとに確定し、カーソル位置へ追記。
- **句読点の自動付与**: 句読点を発話しなくてよい。認識後に形態素解析で「。」「、」を自動挿入する。
- **勝手な半角スペースなし**: 日本語と英数字の間の半角スペースを後処理で除去（英単語間の空白は保持）。
- **音声コマンド**: 「入力キャンセル」「入力復元」「改行」「AをBに修正」「変換戻し」「入力終了」。誤爆防止にプレフィックス語を設定可能。
- **変換戻し**: 直前の入力の読みを復元し、Google CGI API（無料）で文節ごとの変換候補を取得。手／音声（「3番」）で選択。
- **読みベースの再変換**: 同音異義語の誤変換（句読点→苦闘店）を「くとうてんを再変換」で直せる。誤変換でも読みは正しいことを利用する。
- **言い直し**: 読みごと壊れた誤認識は、範囲を選んで言い直すと1発話で置き換わる。
- **PC音声の文字起こし**: Windowsの既定出力をWASAPIで直接取得。Zoom・Meet・動画などの再生音をマイク経由にせず文字起こしできる。音声根拠のある欠落だけを自動再認識し、定型句幻覚と終了後の録音しっぱなしを抑える。

## 構成

```
voxcraft/
├─ server/   Python 認識サーバー（自宅PC常駐）
└─ plugin/   Obsidian プラグイン（録音・挿入・UI）
```

クライアント（プラグイン）は録音とUIだけで軽い。認識はすべてサーバー側。

## セットアップ

### 1. 認識サーバー（自宅PC）

Python 3.10–3.12 推奨（faster-whisper / onnxruntime のホイール都合。3.13+ は未対応の場合あり）。

```powershell
cd server
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
.\run.ps1
```

初回起動時にモデルを自動ダウンロード。
動作確認: ブラウザで `http://localhost:8760/health` が `{"ready": true, "device": "...", ...}` を返せばOK。
Obsidian側からは「設定 → サーバーの状態 → 接続確認」でも確認できる。

#### ログオン時に自動起動する（推奨）

毎回手で起動しなくて済むように、Windowsのスタートアップに登録できる。管理者権限は不要で、
スタートアップフォルダにショートカットを置くだけ（システム設定は変更しない）。

```powershell
cd server
.\install-autostart.ps1            # 登録（次回ログオンから有効）
.\install-autostart.ps1 -Status    # 登録状況とサーバーの稼働状況を表示
.\install-autostart.ps1 -Uninstall # 解除
```

- 今すぐ起動したいときは `autostart.vbs` をダブルクリック（コンソールを出さずに常駐する）。
- ログは `server/server.log`（起動のたびに上書きするので際限なく太らない）。
- 既に起動していれば何もしないので、二重起動でポートを奪い合うことはない。
- 環境変数で設定を変えたい場合は、ログオン時にも効くようユーザー環境変数にする
  （例 `setx VOXCRAFT_MODEL v3-turbo`）。

#### サーバーを手動で制御する

コードや設定の変更後に再起動するときは、ローカル制御スクリプトを使う。

```powershell
cd server
.\control.ps1 status   # 稼働状態とPIDを表示
.\control.ps1 start    # 停止中ならバックグラウンド起動
.\control.ps1 stop     # VoxCraftと確認できたプロセスだけを停止
.\control.ps1 restart  # 停止してからバックグラウンド起動
```

停止はWindowsのプロセス終了を使うため、**文字起こし・録音中には実行しないこと**。
別のプログラムが同じポートを使用している場合は、誤停止を避けるため処理を中止する。

このスクリプトは手動操作専用であり、クラッシュや応答停止を監視するwatchdogではない。
また、VoxCraft停止中はVoxCraft自身が起動要求を受け取れないため、Obsidianからの完全な
遠隔制御には使用できない。将来遠隔制御を追加する場合は、別の常駐コントローラーを置き、
推測困難なトークンによる認証とTailscale等のプライベートネットワーク制限を必須にする。
現在のAPIは認証なしで `0.0.0.0` に待ち受けるため、停止・再起動APIをそのまま追加してはならない。

**GPU高速化（強く推奨）**: NVIDIA GPUがあれば以下でCPU比 約10倍速（RTF 2.1→0.2）。

```powershell
pip install -r requirements-gpu.txt
```

`device`/`compute_type` は自動判定（既定 `VOXCRAFT_DEVICE=auto`）。GPUがあれば `cuda + int8_float16` を選び、
無ければ `cpu + int8` にフォールバックする。`/health` の `"device"` で実際の使用先を確認できる。

どちらの方法でも、Obsidianの「設定 → コミュニティプラグイン」でVoxCraftを有効化し、


### 3. Android（Obsidian Mobile）

1. PCとスマホに [Tailscale](https://tailscale.com/) を入れて同じネットワークに。
2. サーバーURLを `ws://<PCのTailscale IP>:8760/ws` に設定。
3. あとはDesktopと同じ。認識はPCで走るので端末性能に依存しない。

## 使い方

- リボンのマイクアイコン、またはコマンド「音声入力の開始/停止」で録音トグル。
- Zoomなどの相手音声は、Desktopのコマンド「PC音声の文字起こしを開始/停止」を使う。現在選ばれているWindows既定出力が対象になる。
- 話すと息継ぎごとにカーソル位置へ文章が追記される。
- 「入力終了」と言うか、もう一度アイコンを押すと停止。
- 直前の一文を消すときは「入力キャンセル」、戻すときは「入力復元」。画面下部の専用ツールバーからも同じ操作ができる。
- 誤変換は「〇〇を△△に修正」。言い直しの候補が欲しいときは「変換戻し」→候補を数字/クリック/「3番」で選択。

PC音声モードはサーバーが動いているWindows PCの再生音を取得する。初回追加時は
`pip install -r requirements.txt`をもう一度実行し、サーバーを再起動する。
自分のマイク音声は含まれないため、現時点では通話相手側だけが文字起こし対象になる。
PC音声は短い無音ごとに即座に確定せず、既定では約10秒を目標に連結して前後の文脈を保つ。
さらに約30秒ごとに同じ音声を精度優先の設定で再認識し、先に表示した速報テキストを
確定稿へ自動で差し替える。差し替え対象を手で編集していた場合は上書きせず、速報を残す。
PC出力の実音が5分間ない場合は、末尾の認識を完了してから自動停止する。この停止と、
欠落区間の選別再認識・文脈付き定型句フィルターは文字起こしモードだけに作用し、口述には作用しない。

### 誤変換・誤認識を直す（どれを使うか）

誤りの種類で使う手段が変わる。**読みが合っているか**が分かれ目。

| 誤りの種類 | 例 | 手段 |
|---|---|---|
| 同音異義語（読みは正しい） | 句読点 → 苦闘店 | 「くとうてんを再変換」→ 候補を「2番」→「確定」 |
| 場所を指して直したい | 参加 → 傘下 | 誤変換部分を選択 → コマンド「選択範囲を再変換」または「これを再変換」 |
| 読みも壊れている | 訓読点 → 君道大 | 誤り部分を選択 → コマンド「選択範囲を言い直す」（ホットキー推奨）→ 言い直す |
| 英字・外来語（V/B等） | SMTB → SMTV | 候補モーダルの「確定して辞書に登録」、または辞書編集で置換を登録 |

- 短い語を音声だけで指すのは認識が化けやすい（「さんかを」→「3回」）。**選択してから使う経路の方が確実**。
- 同じ読みの誤変換が複数ある場合は、同じ「Aを再変換」を繰り返すと直近から古い箇所へ順に遡る。候補画面の「この箇所をスキップ」では、変更せず一つ前へ進める。通常の口述を再開すると遡り状態は解除される。
- 「言い直し」は認識が化けやすい語なので、コマンド「選択範囲を言い直す」に**ホットキーを割り当てる**のが最も確実。「訂正」「差し替え」でも起動できる（選択範囲があるときだけコマンドになるので、普通の文章を壊さない）。
- 候補モーダルを開いている間は発話が本文に入らない（選択・確定・キャンセルの操作として扱う）。この間だけサーバーは短い発話に速く応える設定になる。
- 何度も出る誤りは辞書に登録すると認識直後に自動修正される（例: `SMTV` → `SMTB`、`スミシン` → `住信`）。

### 句読点（自動付与）

**句読点は発話しなくてよい。** kotoba-whisper は自然な話し言葉にほとんど句読点を打たない
（プロンプトで指示しても増えない）ため、3つの仕組みで補う。

1. **息継ぎ読点**: 短い息継ぎ（2秒以内）で文が切れたら、続きを「、」でつないで挿入する。
   読点の正体は発話の「間」なので、話すリズムがそのまま読点の位置になる。
   長い沈黙（考え中）やコマンド直後には打たない。設定「息継ぎで読点を打つ」でオフ可。
2. **「。」の自動付与**: 丁寧述語（です/ます 系）や終助詞の直後が新しい文の始まりのとき（sudachipy）。
3. **「、」の自動付与**: 逆接・理由の接続助詞（が/けど/ので/から/のに）の後ろ、および
   文頭の接続詞（しかし/また/そして/つまり/例えば 等）の直後（sudachipy）。

誤挿入を避けるため控えめに入れる（文中の連体「〜した人が」等には打たない）。
無効化は `VOXCRAFT_AUTO_PUNCT=0`。sudachipy が無い環境では自動的に無効（起動時に警告）。

### 句読点（「まる」「てん」）を明示的に言う・改行

自動付与に任せず明示的にも入れられる。**記号語は少し間を置いて単独で言う**のが確実:

- 「まる」→ `。`、「てん」→ `、`、「かいぎょう」→ 改行
- Whisper は単独の記号語を同音異義漢字にしがち（てん→点/当店、かいぎょう→開業/会場/海業）。
  よく出る綴りは同音語も吸収するが、**新たに出た誤変換は `userdict.json` の `symbols` に登録**できる（下記）。
- 「かっこ」等の括弧類も**単独チャンク**のときだけ記号化（本文中の「かっこいい」は壊さない）。
- **文の途中で連続して言った読点は変換されない**（「要点」「時点」など本物の"点"を壊さないため）。
  文中の読点は自動句読点に任せるか、打ちたい所で一拍おいて「てん」と言う。
- 間の長さは `VOXCRAFT_SILENCE_SEC`（既定 0.5 秒）。短くすると軽い間で記号語が独立する。

#### 記号語の登録（`symbols`）

観測した誤変換（例「当点」「海業」）を記号に割り当てる。**単独チャンク時のみ**効くので安全。

```json
{
  "symbols": {
    "当点": "、",
    "海業": "改行"
  }
}
```

値は記号そのもの（`、` `。` `！` 等）か、改行は `改行` / `\n`。

### ユーザー辞書（英語・固有名詞の変換 ＝ 育てられる）

**Obsidianから編集できる**: 設定タブ →「ユーザー辞書」→「辞書を開く」、
またはコマンド「ユーザー辞書を編集」。一覧の編集・追加・削除ができ、保存すると即反映される。
サーバー上のファイルを直接触るのでAndroidからも編集できる（Tailscale経由でも可）。

`server/userdict.json` を直接編集してもよい。どちらも保存で自動反映（再起動不要）。

> サーバーは認証を持たないため、辞書の書き込みAPIは「文字列マップのみ・
> 件数500・キー64文字・値128文字」を検証してから保存する。保存は一時ファイル経由なので、
> 失敗しても既存の辞書は壊れない。
**英語・日本語どちらもOK**（キーはひらがな/カタカナ/漢字可）。専門用語・略語・人名・社名を足すほど賢くなる。

```json
{
  "replacements": {
    "ウィンドウズ": "Windows",
    "アンドロイド": "Android",
    "じょうぷらほう": "情プラ法",
    "とうしゃ": "当社"
  }
}
```

**長めの語ほど誤爆が少ない**（短いひらがなキーは本文中の同綴りを巻き込みやすい）。
キーは「読み」でも、実際にWhisperが出す綴りでも良い（後者が確実）。長いキーから順に適用される。

**コツ:**
- JSONは末尾カンマ・`//`コメントも寛容に読むが、壊れていると**サーバーのコンソールに警告**を出す（無言で無効化しない）。
- 認識が音を落とす／全角化するケース（例「ATOK」→全角「Ａトック」）は、全角英数を自動で半角化してから辞書照合する。**実際にWhisperがカタカナでどう出すか**を見て、その綴りをキーに足すのが確実（例 `"Aトック": "ATOK"`）。
- 音節が欠ける（例「ウィンドウズ」→「ウィンドウ」）のは認識側の限界。欠けた綴り自体をキーに登録する。
- **固有名詞・専門用語の誤変換はここで直すのが正攻法**（例「共催」→「協裁」、「趣旨説明」→「収集説明」）。
  モデルが知らない語は設定調整では当たらないので、繰り返し出るものを辞書に足していく。

### 吐息が「はい」等になる（幻覚）対策

無音・吐息をWhisperが「はい」等と誤認識する現象は、内蔵VAD＋無音確率で抑制済み。強すぎ/弱すぎる場合は下表で調整。

## 主な設定（環境変数, `server/config.py`）

| 変数 | 既定 | 説明 |
|---|---|---|
| `VOXCRAFT_MODEL` | kotoba-whisper-v2.0-faster | 認識モデル。略称可（`v3-turbo` / `large-v3` / `medium` / `small`） |
| `VOXCRAFT_DEVICE` | auto | `auto`(GPU優先) / `cuda` / `cpu` |
| `VOXCRAFT_COMPUTE_TYPE` | auto | `auto` / `int8_float16`(GPU) / `int8`(CPU) |
| `VOXCRAFT_BEAM_SIZE` | 5 | 5=精度寄り。GPUなら速度差はほぼ無い。CPUで遅ければ1 |
| `VOXCRAFT_AUTO_PUNCT` | 1 | 句読点の自動付与（sudachipy 必須。未導入なら自動で無効） |
| `VOXCRAFT_HOTWORDS` | 0 | 認識ヒント語。**既定OFF**（長いと認識が空になる不具合のため。下記） |
| `VOXCRAFT_VAD_FILTER` | 1 | 内蔵VADで非発話部分を除去（幻覚対策） |
| `VOXCRAFT_NO_SPEECH_THRESHOLD` | 0.6 | これ超の無音確率セグメントを捨てる（上げると緩く） |
| `VOXCRAFT_SILENCE_SEC` | 0.5 | 息継ぎ確定の無音長（秒） |
| `VOXCRAFT_SYSTEM_SILENCE_SEC` | 0.8 | PC音声で生チャンクを切る無音長（秒） |
| `VOXCRAFT_SYSTEM_MAX_CHUNK_SEC` | 12 | PC音声の生チャンク上限（秒） |
| `VOXCRAFT_SYSTEM_JOIN_SEC` | 10 | PC音声の速報チャンクを連結する目標長（秒） |
| `VOXCRAFT_SYSTEM_JOIN_HOLD_SEC` | 6 | 目標長未満のPC音声を次の発話まで保持する上限（秒） |
| `VOXCRAFT_SYSTEM_JOIN_BREAK_SEC` | 4 | これ以上の無音ではPC音声チャンクを連結しない（秒） |
| `VOXCRAFT_SYSTEM_REFINE` | 1 | PC音声の遅延補正を有効化。0で無効 |
| `VOXCRAFT_SYSTEM_REFINE_WINDOW_SEC` | 30 | 確定稿としてまとめて再認識する長さ（秒） |
| `VOXCRAFT_SYSTEM_REFINE_MIN_SEC` | 8 | 停止時の端数を再認識する最短長（秒） |
| `VOXCRAFT_AUTO_STOP_SEC` | 300 | PC音声文字起こしを自動停止する連続無音（秒）。0で無効 |
| `VOXCRAFT_AUDIBLE_RMS` | 0.0001 | 自動停止で「実音あり」とみなすPC出力RMS |
| `VOXCRAFT_RETRY_GAP_MIN` | 2.0 | 欠落区間を自動再認識する最短秒数 |
| `VOXCRAFT_RETRY_GAP_MAX` | 45.0 | 欠落区間を自動再認識する最長秒数 |
| `VOXCRAFT_RETRY_MIN_RMS` | 0.0015 | 自動再認識に必要な区間全体の最小RMS |
| `VOXCRAFT_RETRY_ACTIVE_RATIO` | 0.03 | 自動再認識に必要な有音フレーム比率 |
| `VOXCRAFT_RETRY_MIN_LOGPROB` | -1.0 | 再認識結果を本文へ採用する最小平均確信度 |
| `VOXCRAFT_STRIP_SPACE` | 1 | 日本語/英数字間スペース除去 |
| `VOXCRAFT_SYMBOLS` | 1 | 記号読み上げ変換 |
| `VOXCRAFT_GOOGLE_CGI` | 1 | 変換戻しにGoogle CGI APIを使う |

### 認識ヒント語(hotwords)が既定OFFな理由

ユーザー辞書の語を Whisper にヒントとして渡す機能だが、**渡す文字列が長くなると
kotoba-whisper が認識結果を丸ごと空にする**（実測: 約120字超で全チャンクが脱落）。
辞書が育つほど壊れる時限爆弾なので既定OFF。安全網として90字で打ち切る。
