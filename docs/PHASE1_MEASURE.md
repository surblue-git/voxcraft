# Phase 1 — ローカルLLMを測る

対象: `docs/REDESIGN_AI_POSTEDIT.md` の Phase 1 / 所要: 準備30分＋実行1〜2時間

自宅PCで走らせる手順。**このリポジトリの外に出るデータは無い**（モデルもローカル）。

---

## 0. なぜ、この測りかたなのか

正解データを作らない。**辞書がそのまま正解**になる。

登録済みの `SMTV → SMTB` は、実際の取材で観測された誤認識と正しい表記の対である。
だから手元のノートに `SMTV` があれば、そこは誤りだと分かっている。
**評価用の文章を書き起こす必要はない** —— 書き起こすと、書いた側の想定しか測れない。

測るのは3つ。

| 問い | 見る数字 |
|---|---|
| **効くか** | 既知の誤りのうち、モデルが直した割合 |
| **危なくないか** | 却下の内訳（読み・数値・語の創作・欠落） |
| **いくらかかるか** | ブロックあたりの所要時間 |

「悪化しないか」は測らなくてよい。門が止めるので**構造的に悪化しない**。

## 1. 準備

### まずブランチを取る

このツールは `main` にまだ入っていない。**ブランチを切り替えないと
`bench_refine.py` が存在しない。**

```powershell
cd <リポジトリ>
git fetch origin claude/wizardly-wright-el1yt0
git checkout claude/wizardly-wright-el1yt0
```

サーバーを常駐させている場合、この測定は**サーバーを止めずに走らせてよい**
（`bench_refine.py` はテキストしか触らない）。ただし辞書の5件を無効化した
コミットを反映するには、サーバーの再起動が要る（`.\server\control.ps1 restart`。
**文字起こし・録音中は実行しないこと**）。

### モデルを入れる

```powershell
winget install Ollama.Ollama
ollama pull qwen3:8b       # 8B。VRAM 8GB 程度から
ollama pull qwen3:14b      # 余裕があれば
ollama list                # 入っているものを確認
```

`ollama serve` が `http://localhost:11434` で待ち受けていれば準備完了。
別のポートや別の実装（llama.cpp のサーバー等）なら `--base-url` で指す。

**思考を出すモデルに注意。** qwen3 系は既定で `<think>…</think>` を吐く。
`refine_llm.py` が剥がすので測定は通るが、**そのぶん生成が遅くなる**
（1ブロックあたり数倍になることもある）。速度を測るなら、プロンプト末尾に
`/no_think` を足すか、思考しないモデルを選ぶ。

**GPUの取り合い。** Whisper と同じGPUに載せると、文字起こし中は両方遅くなる。
測定は認識を回していないときにやる。

### 配線を確かめる（モデル不要・10秒）

```powershell
cd server
.\.venv\Scripts\python.exe bench_refine.py --text <ノート>.md --model stub --dictionary-set default
```

**正しい出力**: 採用100% / 直した量0字 / 「一切直していない」の警告。
既知の誤りが「入力に現れた N 件・直した0件」と出れば、採点も効いている。
ここで N が 0 なら、そのノートには登録済みの誤りが残っていないので測れない
（別のノートを選ぶ）。

### 測るノートを選ぶ

**登録済みの誤りが本文に残っているノート**がよい。0.23.0 のデジ庁会見のノート
（24語を登録しても本文が62箇所そのままだった、あれ）がまさに理想的な対象。

**辞書セットは、そのノートの分野に合わせる。** 決済まわりの取材なら
`--dictionary-set payments`、それ以外は `default`。合っていないと既知の誤りが
1件も見つからず、採点が空振りする。

録音から作り直してもよい（GPUが要る）:

```powershell
.\.venv\Scripts\python.exe bench_refine.py --session 20260806-133113 --limit-sec 900 --model qwen3:8b --dictionary-set default
```

口述の録音は残らない（`recording.py` は文字起こしモードだけ）ので、原稿執筆モードの
入力も当面は会見・取材の生テキストで代用する。自然発話でフィラーも言い直しも入って
いるので、入力の性質としては近い。

## 2. 本番（3回まわす）

### ① 原稿執筆モード・用語集なし —— **これが本命**

```powershell
.\.venv\Scripts\python.exe bench_refine.py --text 会見.md `
    --mode manuscript --model qwen3:8b `
    --dictionary-set default --no-glossary `
    --out 校正後.md --diff 変更.md -v
```

用語集を渡さずに、モデルが文脈だけでどこまで直せるかを見る。
**再設計の中心的な問いはここで決まる** —— 語を1件ずつ登録しなくても本文が直るなら、
辞書の「モデルに教える」役割は要らなくなる。

> 注意: 用語集を渡さないのはモデルへの入力だけで、**門の許可証としては使う**
> （語の門は用語集に無い固有名詞を通さない）。外せるのは辞書の役割の一部であって、
> 項目そのものではない。

### ② 原稿執筆モード・用語集あり

```powershell
.\.venv\Scripts\python.exe bench_refine.py --text 会見.md `
    --mode manuscript --model qwen3:8b --dictionary-set default -v
```

①との差が、**用語集を渡す価値**そのもの。

### ③ 取材モード

```powershell
.\.venv\Scripts\python.exe bench_refine.py --text 会見.md `
    --mode interview --model qwen3:8b --dictionary-set default -v
```

生テキストを正としたまま、表記だけ直せるかを見る。
**採用条件は「違反0件」**。1件でも通れば取材には使えない（口述専用としては可）。

### モデルを並べる

```powershell
.\.venv\Scripts\python.exe bench_refine.py --text 会見.md --dictionary-set default `
    --compare qwen3:8b qwen3:14b gemma3:12b
```

## 3. 読みかた

```
■ qwen3:8b  /  モード: manuscript
  採用            38 件（86.4%）
  却下の内訳
    reading-added          4      ← 対話モードなら問題。原稿執筆では出ない
    invented-term          2      ← 用語集に無い固有名詞を持ち込んだ
  直した量        1,204 字 / 35 ブロック
  所要（中央値）  2.31s / ブロック
  ── 既知の誤り（辞書 = 正解） ──
  入力に現れた既知の誤り  62 件 / 24 種
  モデルが直した          41 件（66.1%）  ← 門の前。モデルの実力
  誤ったまま残った        21 件
  門を通って本文が直る    38 件（61.3%）  ← 実際に効く数
```

**必ず2つ並べて見る。**

- **採用率だけを見ない。** 何もしないモデルは全部の門を通るので採用率100%になる
  （`--model stub` がそれ）。「直した量」が0なら、安全に見えるだけで効いていない。
- **「モデルが直した」と「門を通って本文が直る」の差**が、用語集に載せれば取り返せるぶん。
  この差が大きいなら、結論は「辞書は要らない」ではなく「辞書は**許可証**として要る」。

### 判断

| 見るもの | 採用 | 不採用 |
|---|---|---|
| 取材モードの違反（読み・数値・語） | **0件** | 1件でもあれば取材には使わない |
| 既知の誤りを直した割合 | 高いほどよい。**目安5割** | 1〜2割なら、辞書を置き換えられない |
| 悪化（入力に無い既知の誤りを持ち込む） | 0件 | 1件でも出たらプロンプトを疑う |
| 所要／ブロック | 30秒ブロックの生成より十分速いこと | 認識のレイテンシに影響するなら非同期のまま |

**誤変換が半分になっても、捏造が1件でも通るモデルは取材モードでは採用しない。**

### 残存誤変換を人が数える

`--diff` で出した一覧には、変わったブロックと却下されたブロックだけが載る。
既知の誤り以外（辞書に無い誤変換）は機械では数えられないので、ここを目で見る。
そのとき見つけた対は、そのまま辞書の登録候補になる。

## 測定結果

### 2026-08-28  予備測定（モデル = Claude・原稿執筆モード・用語集なし）

ローカルLLMではない。**方式が成立するかの上限確認**であって、qwen3:8b の代役ではない。
所要時間は測っていない（意味がないため）。入力は擬似的な口述メモ 439字・4ブロック、
辞書は payments。

| | 結果 |
|---|---|
| 門の採用 | 4/4（却下0） |
| 直した量 | 352字 / 4ブロック |
| 既知の誤り | 入力に11件・9種 |
| 同じ出力を取材モードの門へ | **4/4 却下（reading-changed）** ＝ モード分離は実出力でも効く |

**分かったこと。曖昧な漢字語では、AI校正が無条件置換に勝つ。**

同じ本文・同じ辞書で、現行の無条件置換と並べた:

| 箇所 | 種別 | 無条件置換（現行） | AI校正 |
|---|---|---|---|
| 営業利益は現役 → 減益 | 誤り | ✓ | ✓ |
| 四百億円の現役 → 減益 | 誤り | ✓ | ✓ |
| 予診の審査 → 与信 | 誤り | ✓ | ✓ |
| 不良再建 → 不良債権 | 誤り | ✓ | ✓ |
| 債権の蘇生 → 組成 | 誤り | ✓ | ✓ |
| 現役**の行員**（正しい） | 正しい | **✗ 減益の行員** | ✓ |
| **経営**再建の計画（正しい） | 正しい | **✗ 経営債権の計画** | ✓ |
| | | **5/7** | **7/7** |

置換は誤りを直せるが、**同じ語の正しい用法も必ず壊す**。文脈を見ないので、これは
設定では避けられない。AI校正は7/7で、直すべきものを直し、直してはいけないものに
触らなかった。

**固有名詞は用語集が要る。** 直せなかったのは `水尾銀行 → みずほ銀行`、
`一軒米氏 → eKYC`、`ウィンドウズ → Windows` の3件で、すべて固有名詞。プロンプトが
「用語集にあるものだけ」と制限しており、門も用語集に無い固有名詞を通さない。
**これは失敗ではなく設計どおり**で、結論は「辞書は要らない」ではなく次のとおり。

> **辞書は2種類に分かれる。** 曖昧な漢字語（現役・再建・予診・蘇生）は登録から外して
> AI校正に任せる。固有名詞（PayPay・みずほ銀行・eKYC）は登録を残し、**許可証**として使う。

### 辞書の健康診断（実データ・**対応済み**）

`audit_dictionary` を payments 辞書に当てた結果、**それ自体が普通に使われる漢字語**が5件
見つかった。無条件置換は文脈を見ないので、正しい用法まで壊していた:

| 登録 | 壊れていた例 | 状態 |
|---|---|---|
| 予診 → 与信 | 予診票に記入 → **与信票に記入** | 無効化 |
| 余震 → 与信 | 余震が続いている → **与信が続いている** | 無効化 |
| 再建 → 債権 | 経営再建の計画 → **経営債権の計画** | 無効化 |
| 現役 → 減益 | 現役の行員 → **減益の行員** | 無効化 |
| 蘇生 → 組成 | 細胞の蘇生 → **細胞の組成** | 無効化 |

0.23.0 のプレビューは**登録時**の事故を防ぐもので、登録済みのこれらには効かなかった
（毎回の認識で黙って発火していた）。

**削除ではなく `enabled: false` にした。** 実際に観測された誤認識の記録には値があり、
AI校正が扱うべき語の実例そのものだから。理由は `note` に残してあるので、後から
同じ語を登録し直す事故も防げる。旧編集UIは無効項目を表示しないが、
`update_profile_maps` が保全するので、UIから保存しても消えない（往復で確認済み）。

**曖昧でない登録はそのまま。** `県役 → 減益`（ASRの崩れ）と
`不良再建 → 不良債権`（文脈を含む長いキー）は残っていて、いまも効く。
これが「置換に向く登録」と「AI校正に向く登録」の境目になる。

適用後: 有効な置換 140 → 135件、漢字の高リスク **0件**、壊れる文 0件。
