# Phase 1 — ローカルLLMを測る

対象: `docs/REDESIGN_AI_POSTEDIT.md` の Phase 1 / 所要: 準備30分＋実行1〜2時間

自宅PCで走らせる手順。**このリポジトリの外に出るデータは無い**（モデルもローカル）。

---

## 0. なぜ、この測りかたなのか

正解データを作らない。**辞書がそのまま正解**になる。

登録済みの `SMTV → SMTB` は、実際の取材で観測された誤認識と正しい表記の対である。
だから手元のノートに `SMTV` があれば、そこは誤りだと分かっている。
**評価用の文章を書き起こす必要はない** —— 書き起こすと、書いた側の想定しか測れない。

測るのは3つ。

| 問い | 見る数字 |
|---|---|
| **効くか** | 既知の誤りのうち、モデルが直した割合 |
| **危なくないか** | 却下の内訳（読み・数値・語の創作・欠落） |
| **いくらかかるか** | ブロックあたりの所要時間 |

「悪化しないか」は測らなくてよい。門が止めるので**構造的に悪化しない**。

## 1. 準備

### モデルを入れる

```powershell
# Ollama を入れて、日本語の効くモデルを引く
winget install Ollama.Ollama
ollama pull qwen3:8b
ollama pull qwen3:14b     # VRAM に余裕があれば
```

`ollama serve` が `http://localhost:11434` で待ち受けていれば準備完了。
別のポートや別の実装（llama.cpp のサーバー等）なら `--base-url` で指す。

### 配線を確かめる（モデル不要・10秒）

```powershell
cd server
.\.venv\Scripts\python.exe bench_refine.py --text <ノート>.md --model stub --dictionary-set default
```

**正しい出力**: 採用100% / 直した量0字 / 「一切直していない」の警告。
既知の誤りが「入力に現れた N 件・直した0件」と出れば、採点も効いている。
ここで N が 0 なら、そのノートには登録済みの誤りが残っていないので測れない
（別のノートを選ぶ）。

### 測るノートを選ぶ

**登録済みの誤りが本文に残っているノート**がよい。0.23.0 のデジ庁会見のノート
（24語を登録しても本文が62箇所そのままだった、あれ）がまさに理想的な対象。

録音から作り直してもよい（GPUが要る）:

```powershell
.\.venv\Scripts\python.exe bench_refine.py --session 20260806-133113 --limit-sec 900 --model qwen3:8b --dictionary-set default
```

口述の録音は残らない（`recording.py` は文字起こしモードだけ）ので、原稿執筆モードの
入力も当面は会見・取材の生テキストで代用する。自然発話でフィラーも言い直しも入って
いるので、入力の性質としては近い。

## 2. 本番（3回まわす）

### ① 原稿執筆モード・用語集なし —— **これが本命**

```powershell
.\.venv\Scripts\python.exe bench_refine.py --text 会見.md `
    --mode manuscript --model qwen3:8b `
    --dictionary-set default --no-glossary `
    --out 校正後.md --diff 変更.md -v
```

用語集を渡さずに、モデルが文脈だけでどこまで直せるかを見る。
**再設計の中心的な問いはここで決まる** —— 語を1件ずつ登録しなくても本文が直るなら、
辞書の「モデルに教える」役割は要らなくなる。

> 注意: 用語集を渡さないのはモデルへの入力だけで、**門の許可証としては使う**
> （語の門は用語集に無い固有名詞を通さない）。外せるのは辞書の役割の一部であって、
> 項目そのものではない。

### ② 原稿執筆モード・用語集あり

```powershell
.\.venv\Scripts\python.exe bench_refine.py --text 会見.md `
    --mode manuscript --model qwen3:8b --dictionary-set default -v
```

①との差が、**用語集を渡す価値**そのもの。

### ③ 取材モード

```powershell
.\.venv\Scripts\python.exe bench_refine.py --text 会見.md `
    --mode interview --model qwen3:8b --dictionary-set default -v
```

生テキストを正としたまま、表記だけ直せるかを見る。
**採用条件は「違反0件」**。1件でも通れば取材には使えない（口述専用としては可）。

### モデルを並べる

```powershell
.\.venv\Scripts\python.exe bench_refine.py --text 会見.md --dictionary-set default `
    --compare qwen3:8b qwen3:14b gemma3:12b
```

## 3. 読みかた

```
■ qwen3:8b  /  モード: manuscript
  採用            38 件（86.4%）
  却下の内訳
    reading-added          4      ← 対話モードなら問題。原稿執筆では出ない
    invented-term          2      ← 用語集に無い固有名詞を持ち込んだ
  直した量        1,204 字 / 35 ブロック
  所要（中央値）  2.31s / ブロック
  ── 既知の誤り（辞書 = 正解） ──
  入力に現れた既知の誤り  62 件 / 24 種
  モデルが直した          41 件（66.1%）  ← 門の前。モデルの実力
  誤ったまま残った        21 件
  門を通って本文が直る    38 件（61.3%）  ← 実際に効く数
```

**必ず2つ並べて見る。**

- **採用率だけを見ない。** 何もしないモデルは全部の門を通るので採用率100%になる
  （`--model stub` がそれ）。「直した量」が0なら、安全に見えるだけで効いていない。
- **「モデルが直した」と「門を通って本文が直る」の差**が、用語集に載せれば取り返せるぶん。
  この差が大きいなら、結論は「辞書は要らない」ではなく「辞書は**許可証**として要る」。

### 判断

| 見るもの | 採用 | 不採用 |
|---|---|---|
| 取材モードの違反（読み・数値・語） | **0件** | 1件でもあれば取材には使わない |
| 既知の誤りを直した割合 | 高いほどよい。**目安5割** | 1〜2割なら、辞書を置き換えられない |
| 悪化（入力に無い既知の誤りを持ち込む） | 0件 | 1件でも出たらプロンプトを疑う |
| 所要／ブロック | 30秒ブロックの生成より十分速いこと | 認識のレイテンシに影響するなら非同期のまま |

**誤変換が半分になっても、捏造が1件でも通るモデルは取材モードでは採用しない。**

### 残存誤変換を人が数える

`--diff` で出した一覧には、変わったブロックと却下されたブロックだけが載る。
既知の誤り以外（辞書に無い誤変換）は機械では数えられないので、ここを目で見る。
そのとき見つけた対は、そのまま辞書の登録候補になる。
